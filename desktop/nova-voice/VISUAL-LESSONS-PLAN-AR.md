# خطة تطوير الدروس المرئية — Nova Voice

> **الحالة: خطة مقترحة للتنفيذ، وليست ميزات منفّذة.** المرجع الحالي هو الإصدار
> **0.5.1**. هذه الوثيقة لا تغيّر البرنامج أو حزمة RAR المسلّمة، ولا تعلن إطلاقًا جديدًا.

## 1. الفكرة الأساسية

تطوير السبورة من «نص يُكتب مع الصوت» إلى **مشاهد تعليمية من قوالب واضحة**:

- أعداد وعدّ أشياء: تفاح، كرات، أقلام، مكعبات ودوائر.
- جمع وطرح بتحريك مجموعات مرئية يمكن عدّها فعلًا.
- أشكال هندسية ومقارنات وخط أعداد وكسور في دفعات لاحقة.
- رسوم جغرافية: جبل، قمة، سفح، وادٍ، هضبة، سهل ونهر.
- خرائط مبسطة مع تسميات وأسهم وإبراز مناطق، بعد اختيار خريطة موثوقة مناسبة للمنهج.

يظل المنتج تطبيق Windows مستقلًا يصدر **ملف HTML واحدًا يعمل دون إنترنت** بعد
التجهيز. لا حاجة إلى خدمة ذكاء اصطناعي، أو Web Speech API، أو خرائط شبكية، أو
اشتراك، أو محرك ثلاثي الأبعاد. هدف الأجهزة ذات 4GB يُقاس لاحقًا، ولا يُقدَّم كضمان.

**الاختيار المقصود:** قوالب وقيم محددة يراجعها المدرّس، لا وعد بفهم أي شرح حرّ
واختراع رسوم صحيحة تلقائيًا. العدد «تفاحتان» يجب أن ينتج جسمين بالضبط، لا صورة
مولّدة قد تحتوي عددًا خاطئًا.

## 2. أول أساس: فصل المعروض عن المنطوق

كتابة «زائد» بدل `+` و«يساوي» بدل `=` توضح القراءة المطلوبة لمحرك الصوت، لكن
**في 0.5.1 النص نفسه أساس العرض والنطق**؛ كتابة الكلمات تجعلها تظهر أيضًا على
السبورة. النطق يظل بحاجة إلى معاينة بالنموذج الحقيقي المختار.

التطوير المقترح يعطي كل مقطع حقلين واضحين:

| الحقل | مثال |
| --- | --- |
| النص المعروض | `2 + 3 = 5` |
| النص المنطوق | اثنان زائد ثلاثة يساوي خمسة. |
| شرح اختياري أطول | لدينا تفاحتان. نضيف إليهما ثلاث تفاحات. يصبح المجموع خمس تفاحات. |

وللإنجليزية يمكن للمدرّس كتابة `Two plus three equals five.` واختيار نموذج English
مناسب. البرنامج لا يترجم الشرح أو يختار لغة الأرقام بدلًا من المدرّس.

### ضوابط هذا الفصل

1. وضع **«نص عادي»** يبقى كما هو؛ إذا لم يوجد نص منطوق منفصل، يستخدم النص الحالي.
2. النص الأصلي محفوظ، ولا تُستبدل الرموز عالميًا أو خفية داخل السكريبت.
3. اقتراح قراءة الرموز يعمل داخل **قالب حساب مختار صراحةً**، لا على الشرطات في
   التواريخ أو علامات مثل `C++`. المعلّم يراجع ويقبل النص المقترح أو يكتبه بنفسه.
4. اقتراحات الرموز: `+` زائد، `−` ناقص، `×` مضروب في، `÷` مقسوم على، `=` يساوي.
   هذه معانٍ تعليمية عامة، وليست ضمانًا للنطق أو للصياغة المناسبة لكل جملة.
5. يُفحص توافق **لغة النص المنطوق** مع الصوت. لا يُلغى حارس اللغة، ولا تُمرَّر
   العربية إلى صوت إنجليزي والعكس. العرض الرياضي وحده لا يحدد لغة الكلام.
6. تُعزل جهة كتابة المعادلة عن RTL حتى لا تنقلب أطرافها. يُتاح اختيار شكل الأرقام
   `123` أو `١٢٣` مع بقاء القيم الحسابية واضحة ومراجعة اتجاه العرض حسب المنهج.
7. أسماء الأشياء وصيغ المفرد والمثنى والجمع لا تُولَّد بوعود لغوية عامة؛ تبدأ
   بقوالب محدودة مُراجَعة، وتظل خانة الشرح قابلة للتحرير والمعاينة.

## 3. تجربة إنشاء الدرس المقترحة

1. **اختر نوع المشهد:** نص / عدّ / جمع / طرح، ثم الأنواع اللاحقة عند اكتمالها.
2. **حدد المحتوى:** مثلًا «تفاح، المجموعة الأولى 2، العملية جمع، المجموعة الثانية 3».
3. **راجع المعروض والمنطوق:** لا يختلط الشرح المكتوب بما سيُقرأ فعلًا.
4. **اختر الصوت والمظهر:** راوٍ واحد للغة واحدة، أو أدوار متعددة كما في الوضع الحالي.
5. **معاينة مرئية بلا صوت** ثم معاينة صوتية قصيرة عند الحاجة.
6. **توليد HTML بالنص والصوت معًا** باستخدام المسار الحالي، مع بقاء مسار الخطوتين.

تُضاف إعدادات المشهد داخل واجهة التطبيق المنظمة، وتظهر حقول النوع المختار فقط.
لا نضع جميع خيارات الحساب والخرائط أمام المدرّس في وقت واحد. تتبع الواجهة ألوان
المشروع وRTL وأحجام الأزرار الحالية، دون تغيير ERP أو ملف اللغة المقفل.

## 4. ترتيب التنفيذ ومخرجات كل مرحلة

| المرحلة | النطاق | المخرج المطلوب قبل الانتقال |
| --- | --- | --- |
| 0 — أساس البيانات والصوت | فصل المعروض والمنطوق، بيانات مشهد مُتحقَّق منها، توافق الملفات القديمة | درس نصي قديم يعمل كما كان، ومعادلة تُعرض بالرموز وتُقرأ بالنص المنفصل |
| 1 — الحساب المرئي | عدّ، جمع وطرح بأشياء SVG محلية | نسخة تجريبية قابلة للاستخدام: تفاحتان + ثلاث تفاحات، وخمسة أشياء نزيل منها اثنين |
| 2 — تنويع الرياضيات | أشكال وألوان، مقارنة مجموعتين، خط أعداد، ثم كسور بسيطة | قوالب صغيرة مستقلة، لا محرر رسم شامل |
| 3 — الجغرافيا والرسوم العلمية | تضاريس أولًا، ثم خرائط مبسطة موثوقة وتسميات | درس «أجزاء الجبل»، وبعده خريطة مختارة قابلة للإبراز والشرح |
| 4 — نشاط المتعلم | اختيار إجابة، عدّ بالنقر، مطابقة؛ السحب والإفلات لاحقًا إن لزم | نشاط يعمل بالماوس واللمس ولوحة المفاتيح، ولا يكشف الحل تلقائيًا |

**أول دفعة مقترحة للإصدار التالي:** المرحلتان 0 و1 فقط. اسم **0.6.0** اقتراح
للترقيم بعد اكتمال الاختبارات، وليس إصدارًا موجودًا الآن. لا موعد ثابت قبل تثبيت
نطاق الدفعة واختبار النموذج الأولي.

## 5. الدفعة الأولى: العدّ والجمع والطرح

### نطاق عملي محدود

- مكتبة أولى صغيرة: تفاحة، كرة، قلم، مكعب ودائرة؛ أصول SVG محلية خفيفة.
- الأعداد المرئية حتى 20؛ في الجمع تكون النتيجة ضمن هذا الحد.
- طرح غير سالب: لا يُسمح بإزالة أشياء أكثر من الموجودة. السالب يُشرح لاحقًا بخط الأعداد.
- لا تقسيم على صفر، ولا صيغ حرة أو تنفيذ تعبيرات برمجية. العمليات المدعومة قيم وأنواع محددة.
- الأعداد الأكبر تُؤجَّل أو تُعرض بمجموعات/عشرات في قالب مستقل، بدل مئات الأيقونات.
- القيم الحسابية تُتحقَّق محليًا؛ لا يعتمد عدد الرسومات على تخمين النص الحرّ.

### مثال: تفاحتان وثلاث تفاحات

| جزء الشرح | ما يظهر على السبورة | الكلام المقترح |
| --- | --- | --- |
| المعطيات | تفاحتان في مجموعة واضحة | لدينا تفاحتان. |
| الإضافة | ثلاث تفاحات تدخل إلى مجموعة ثانية مع علامة الجمع | نضيف إليهما ثلاث تفاحات. |
| النتيجة | خمس تفاحات مع إبراز المجموع و`2 + 3 = 5` | يصبح المجموع خمس تفاحات. |

هذه مراحل مرئية داخل المشهد، مرتبطة بمقاطع الشرح. **لا نمسح السبورة بين كل كلمة
أو حركة صغيرة**؛ المسح يظل عند الانتقال إلى خطوة/مشهد آخر. في الطرح تتحرك الأشياء
المحذوفة إلى منطقة منفصلة أو تصبح باهتة، حتى يرى الطفل «الموجود / المزال / المتبقي».

### التدريس مقابل التدريب

- **وضع الشرح:** إظهار النتيجة مع جملة النتيجة، لا قبلها.
- **وضع التدريب:** سؤال مثل «كم أصبح العدد؟» دون كشف الحل، ثم إظهار الإجابة
  بإجراء صريح. يمكن فصل السؤال والإجابة إلى خطوتين مع منع الانتقال التلقائي
  من تجاوز بوابة الحل في هذا النوع الجديد.
- لا حسابات مُخترعة من فقرة مبهمة، ولا تغيير لما كتبه المدرّس دون مراجعة.
- ملف التدريب المحلي ليس امتحانًا آمنًا ضد الغش؛ الإجابات المضمّنة يمكن كشفها
  بفحص الملف، حتى لو لم تظهر في واجهة الطالب.

## 6. الأشكال وأفكار أخرى قابلة لإعادة الاستخدام

### الرياضيات

- دائرة، مربع، مثلث ومستطيل: إبراز الأضلاع والزوايا وتسميات يحددها المدرّس.
- أكثر/أقل/يساوي بمقارنة مجموعتين، لا قراءة العلامة وحدها.
- تسلسل وعدّ تصاعدي وتنازلي، ثم خط أعداد للجمع والطرح.
- نصف وربع برسوم مقسمة بالتساوي، بعد اختبار التمثيل والقراءة.
- أعمدة بسيطة لعرض بيانات يكتبها المدرّس: مثل عدد التفاح والكرات، لا إحصاءات مخترعة.

### اللغة والعلوم

- حرف أو كلمة مع شكل من المكتبة، ثم مطابقة الكلمة بالشكل.
- أجزاء النبات: جذر، ساق، أوراق؛ تسميات وأسهم مرتبطة بالشرح.
- دورة الماء: شمس، تبخر، سحب ومطر؛ رسم توضيحي متدرج.
- قراءة الساعة بعقارب محلية، كقالب مستقل له قواعد ونطق يُراجعان.

هذه توسعات لاحقة تستفيد من محرك المشهد نفسه؛ لا تدخل كلها في أول دفعة.

## 7. الجبال والخرائط

### البداية: رسم تضاريس توضيحي

مشهد لجبل ووادٍ وسهل ونهر، مع نقاط تسمية وأسهم. يبرز الجزء المعني عند بداية
مقطع شرحه. يمكن إظهار «قمة / سفح / وادٍ» بالتدريج أو ترك التسميات للتمرين.
يُوسم الرسم **«رسم توضيحي غير مقياسي»**؛ لا تُختلق منه ارتفاعات أو مسافات حقيقية.

### بعدها: خريطة حقيقية مبسطة

- يحدد المدرّس الدولة/المنطقة والصف الدراسي؛ مثل مصر أو خريطة للعالم بحسب الدرس،
  ولا تُفترض خريطة سياسية تلقائيًا.
- اختيار بيانات جغرافية موثوقة مناسبة للمنهج، وتثبيت مصدرها وإصدارها وترخيصها.
  لا تُقدَّم حدود مرسومة تخمينيًا أو صورة مولّدة على أنها خريطة دقيقة.
- تجهيز أصل SVG مبسّط محليًا، وإرفاق الإسناد/الترخيص. لا تحميل بلاطات أو اعتماد
  على خدمة خرائط أثناء الدرس.
- أدوات أولى: تسمية مكان، إبراز منطقة، سهم اتجاه، مسار/نهر ومعاينة عامة.
  التكبير والتحريك يُضافان فقط إذا أثبتت تجربة الهاتف الحاجة إليهما.
- التسميات العلمية والأماكن والمعلومات يراجعها المدرّس؛ لا مولد معلومات جغرافية تلقائي.
- الاستيراد العام لملفات SVG/GeoJSON ليس ضمن البداية؛ يبدأ العمل بمكتبة مُراجَعة
  حتى لا تتحول الخريطة إلى مدخل لكود أو روابط خارجية غير آمنة.

## 8. التزامن والمسح والحفظ

1. **ساعة الصوت هي المرجع** عند وجود صوت؛ حركة الصور لا تُدار بمؤقت مستقل ينجرف عنه.
2. تبدأ مراحل المشهد عند حدود مقاطع/سطور الشرح المقاسة من PCM. الحركة داخل المقطع
   تقريبية، وليست محاذاة لكل كلمة أو فونيم، ما لم يُضف قياس مستقل لذلك مستقبلًا.
3. الإيقاف يجمد الحركة، والاستكمال يتابعها. التقديم والترجيع يعيدان بناء حالة
   المشهد من الوقت الحالي، بدل تكرار الإضافة أو ترك تفاحة «عالقة» من تشغيل سابق.
4. إعادة الخطوة تصفر النشاط؛ والتنقل السريع يبقي آخر وجهة فقط، كما في المسح الحالي.
5. المسح يشمل النص والأشكال معًا عند تغيير المشهد؛ الصوت الجديد يبدأ بعده، ولا يتغير PCM.
6. تقليل الحركة يعرض الحالات المناسبة مباشرةً دون إخفاء المعنى أو إجبار الطفل على الحركة.
7. حفظ التخصيصات يزيل الأقنعة والإطارات وحالة النشاط المؤقتة من النسخة المحفوظة.
   لا يُحفظ تقدم طفل أو بياناته الشخصية تلقائيًا تحت اسم «تخصيصات».
8. الصوت والبيانات والرسوم تبقى داخل HTML. لا تُضاف مكتبة من CDN أو خط شبكي مطلوب للتشغيل.

## 9. تصميم فني يتفق مع المشروع الحالي

### لماذا ليست إضافة صور فقط؟

في 0.5.1 يوجد `BoardRow(speaker, text)`، ويُشتق الكلام من `row.text`. ملف الدرس
يحمل `schema: 1` وبصمة تتحقق من النص والصفوف، وخريطة التوقيت مرتبطة ببصمة الدرس.
إضافة نص منطوق أو رسوم خفية إلى هذا المسار ستكسر التحقق أو تربط الصوت ببيانات خاطئة.
لذلك تُصمَّم ترقية بيانات واضحة، لا تجاوز للتحقق الموجود.

### العقود المقترحة

- مخطط درس جديد، **schema 2 مقترح**، مع محول قراءة صريح للملفات القديمة schema 1.
- حقول منطقية للمعروض والمنطوق، ونوع مشهد وقيمه، وأصوله وأحداثه المرتبطة بمعرّفات
  المقاطع. الأسماء النهائية تُحسم أثناء التنفيذ، وليست صيغة سكريبت مدعومة الآن.
- في الملفات القديمة: المعروض والمنطوق لهما السلوك الحالي، ولا تُعاد كتابة الملف الأصلي.
- تُحفظ معطيات القالب والمعروض والمنطوق وروابط المقاطع كاملةً؛ إعادة فتح HTML تعيد
  تصميم الدرس كما حُفظ، ولا تحاول تخمين المشاهد ثانيةً من السكريبت وحده.
- كل مقطع مصوّت يحتاج نص نطق غير فارغ. المشاهد الصامتة المختلطة وسط درس صوتي
  ليست افتراضًا خفيًا في أول دفعة؛ تُحدد قواعدها لاحقًا إذا طُلبت. المعاينة المرئية
  دون توليد صوت تبقى متاحة.
- بصمات وتحقق يربطان الصوت بنص النطق والقيم الدلالية ذات الصلة. تغيير الأعداد أو
  الكلام يبطل التوقيت/الصوت القديم عند اللزوم؛ أما لون تفاحة أو موضع تسمية فلا
  ينبغي أن يفرضا توليد الصوت من جديد. يُصمَّم هذا الفصل مع توافق توقيت النسخة القديمة.
- يبقى **مرمّز متدفق واحد لكل خطوة** وحدود المقاطع من عينات الصوت النهائية؛ لا
  إنشاء ملف صوت لكل تفاحة، ولا إدراج صمت مصطنع كي يلحق الرسم بالصوت.
- عند نقص بيانات التوقيت الجديدة: رسالة/عرض ثابت آمن بدل حركة توحي بدقة غير موجودة.
  يبقى fallback الخاص بالنصوص القديمة كما هو.

| `whiteboard.html/js/css` | منطقة للأشكال والتسميات، وتخطيط هاتف، وإدخالها مع النص في مجموعة المسح |
| `whiteboard-appearance.js` | حفظ بيانات التصميم وإزالة حالة الرسم/المسح/النشاط المؤقتة |
| `assets/scenes/` المقترح | مكتبة SVG مُراجَعة وبيانات المصدر/الترخيص عند الحاجة |
| الاختبارات والتغليف والأمثلة | إدراج الملفات الجديدة فعليًا في الحزمة، مع أمثلة قديمة وجديدة |

تُضمّن الملفات الجديدة في HTML عبر المصدّر الحالي؛ لا نفترض عمل استيرادات شبكية
أو JavaScript modules خارجية عند فتح `file://`. تُستخدم SVG مع إعادة استخدام
الأصول ومعرّفات فريدة، لا لوحات raster كبيرة أو مكتبات رسم ثقيلة.

## 10. الخفة والسلامة وإمكانية الوصول

- ميزانية أولية مقترحة: 20 شيئًا للعدّ في الدفعة الأولى؛ حد إجمالي حذر للأشكال
  النشطة يُراجع بالقياس، لا عدد غير محدود من العناصر. الأعداد الكبيرة لها تمثيل مجموعات.
- الحفاظ على حدود النص/الصفحات/HTML/الصوت الحالية، وإضافة حدود لحجم الأصول
  وتعقيد المسارات والتسميات. لا صمت أو قطع محتوى أو تخفيض جودة خفي عند تجاوزها؛ تظهر رسالة.
- لا SVG غير مُراجع يحتوي scripts أو `foreignObject` أو مراجع خارجية، ولا HTML
  حر داخل التسميات. الإدخال نصوص وقيم مقيدة، لا أوامر قابلة للتنفيذ.
- وصف نصي للمشهد، وتباين واضح، وعدم الاعتماد على اللون وحده لتمييز المجموعات.
- لوحة مفاتيح ولمس للأنشطة؛ لا يكون السحب الوسيلة الوحيدة للإجابة.
- لا حفظ أسماء الأطفال أو إجاباتهم أو اتصال بالشبكة دون مسار صريح يختاره المستخدم.
- اختبار Windows فعلي وجهاز 4GB مستهدف قبل وصفه بأنه مناسب؛ تُسجل RAM/CPU
  وسرعة فتح الملف وحجم HTML مع وصف الجهاز. لا تعوض اختبارات Linux هذا القياس.
- لا تغيير لمحرك Piper أو ضمان جديد لجودة RP أو إصلاح ح في كريم ضمن هذا العمل المرئي.

## 11. معايير قبول أول نسخة مرئية

- [ ] المعادلة تعرض `2 + 3 = 5` بينما الكلام يأتي من خانة النطق، لا من الرموز.
- [ ] `2 + 3` يرسم خمسة أشياء بالضبط؛ و`5 − 2` يترك ثلاثة بالضبط.
- [ ] الصفر وحدود العدد والقيم المرفوضة وحالات الطرح غير الصالح مغطاة بالاختبارات.
- [ ] التوقف والتقديم والترجيع وإعادة التشغيل لا تكرر الأشياء ولا تغير النتيجة.
- [ ] السؤال لا يكشف حله أو ينطق الإجابة قبل الإجراء المخصص، حتى مع إعدادات التشغيل التلقائي.
- [ ] المسح يشمل الرسوم والنص، والتنقل السريع والحفظ أثناءه لا يتركان قناعًا أو حالة عالقة.
- [ ] HTML محفوظ يعاد فتحه offline بالنص والصوت والتوقيت والمظهر الصحيحين.
- [ ] الملفات القديمة والأمثلة والنص الحرفي والألوان والشخصيات والمساران الأصليان تبقى سليمة.
- [ ] قيود اللغة تطبق على النص المنطوق، وتغيير الكلام لا يعيد استخدام صوت/توقيت غير مطابق.
- [ ] الهاتف عند 360px وRTL وتقليل الحركة ولوحة المفاتيح تعمل دون تجاوز عرض الصفحة.
- [ ] لا طلبات شبكية للتشغيل، ومعرّفات SVG فريدة ومدخلات غير موثوقة مرفوضة.
- [ ] استماع فعلي لعينة عربية وأخرى English بالنموذجين المختارين؛ ليس WAV اختبار صامتًا فقط.
- [ ] حزمة مصدر مجرّبة بعد فكها، وتحقق SHA/CRC وإدراج الأصول والأدلة الجديدة؛ لا Actions/EXE ضمن التسليم الحالي.

نجاح الاختبارات الحالية خط أساس، **وليس دليلًا على اكتمال هذه المزايا المقترحة**.
يُعاد اختبارها مع الحالات الجديدة ثم يُراجع الدرس عمليًا قبل إصدار الحزمة.

## 12. توصية التنفيذ والقرارات الباقية

**نبدأ بفصل المعروض والمنطوق + العدّ + الجمع والطرح، ثم نوسّع محرك المشهد نفسه
إلى الأشكال والجغرافيا.** بذلك نحصل أولًا على درس تفاح صحيح ومفيد، بدل نصف محرر
حساب ونصف خريطة في إصدار واحد.

قبل دفعة الخرائط نحدد: الدولة/المنطقة، والصف/المنهج، ومصدر الخريطة المقبول.
وقبل تعميم اقتراحات النطق نحدد: فصحى أم صياغة مدرسية عامية، ونراجع النموذج الصوتي.
هذه قرارات محتوى، ولا تستدعي تغيير السكريبت القديم أو اختيار صوت/جنس نيابة عن المستخدم.

**خارج النطاق الأول:** فهم النص الحر بالذكاء الاصطناعي، رسم أي شيء من وصف غير
مقيد، تحويل الكلام إلى فيديو، رسوم 3D، GIS كامل، خرائط حية، تصحيح مفتوح لإجابات
الطلاب، أو منصة امتحانات سحابية.
